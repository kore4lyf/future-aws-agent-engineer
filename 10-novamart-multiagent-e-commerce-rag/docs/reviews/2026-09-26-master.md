## Summary

Change adds Pydantic (validation library) input and output models for all agent tools in the foundation deployment slice.
Direction matches project rules that ask for Pydantic at tool limits and clean layers.
Two blocking defects remain that will crash real calls.
Several larger contract and safety gaps also need fixes before merge.

## Blockers

### 🔴 Missing phone field crashes tier lookup, `src/agents/inventory/schema.py:41`

**Problem**: `CustomerProfile` marks `phone` as required. Seed customers have no `phone` value. Every real lookup builds the model from a stored record, so validation fails for all four seeded customers. I ran a small check that confirms the failure.

**Why it matters**: `get_customer_tier` is called for account questions and return flows. It will raise instead of returning a profile, so tier logic never runs.

**Suggested fix**: Make `phone` optional with a default of `None`, or drop it from the profile, then include it only when the stored record has it. Add handling so a bad record returns a clean error model instead of raising.

### 🔴 Policy parallel search passes raw agent results to string fields, `src/agents/policy/__init__.py:80`

**Problem**: `search_all_policies` hands retriever results straight to `SearchAllPoliciesOutput` fields typed as `str`. Retriever calls return agent result objects, not plain strings. Pydantic rejects objects for `str` fields. I ran a small check that confirms this reject behavior. Old code used string formatting, which accepts any object.

**Why it matters**: Any policy question will make the tool raise instead of returning combined passages. The policy path is central to the product, so this breaks a main flow.

**Suggested fix**: Convert each retriever result to string with `str()` before building the output model. Keep the old joined synthesis as the main text. Wrap the build in error handling that returns empty strings plus a note when a retriever has no result.

## Major

### 🟠 Refund write can create records for unknown orders, `src/agents/refund/tools.py:67`

**Problem**: `initiate_refund` calls `update_item` with no existence check. DynamoDB (managed database) creates a new record when the keys are unknown. So a wrong or invented `order_id` will create a fresh order marked as returned. There is also no check for orders already marked returned, so repeat calls keep issuing new references.

**Why it matters**: Bad data enters the orders table. Later lookups will see false returned orders. Support reports become wrong.

**Suggested fix**: Add a condition that the order must already exist, and return a clean not found error when it does not. Consider reading the order first and refusing repeat returns.

### 🟠 Tool validation failures escape as crashes, `src/agents/inventory/tools.py:57`

**Problem**: Tools catch `ClientError` only. Pydantic validation failures raise `ValidationError`, which is not caught. New code adds many model builds from stored data, so mismatched records now raise. Affected tools include `check_order_status`, `get_customer_tier`, `list_customer_orders`, `get_full_workflow_context` and `get_inventory_context`.

**Why it matters**: One odd record turns a tool call into a crash. The agent sees a failure instead of a clean error model. There is no safety net of tests in this change, so runtime safety matters more.

**Suggested fix**: Catch broad errors around model builds and return the matching error output model with the message set. Keep `ClientError` handling as is and add the same shape for validation failures.

### 🟠 Same workflow field typed two ways, `src/agents/communication/schema.py:22`

**Problem**: Communication models type `inventory_agent` as `str` or `None`. Refund models type the same stored field as `dict` or `None`, see `src/agents/refund/schema.py:16`. Both read the same DynamoDB value. Both cannot be right at once. One side will reject real values.

**Why it matters**: Context sharing between agents breaks. Refund needs inventory facts, communication needs all sections. A type reject on read stops the flow.

**Suggested fix**: Agree on one shape for stored agent results across all schemas. If stored values are text, use `str` everywhere. If they are maps, use a shared model everywhere. Add a short comment that names the chosen shape.

### 🟠 Policy tool return shape changed from text to object, `src/agents/policy/__init__.py:37`

**Problem**: `search_all_policies` used to return joined text. It now returns a dumped model object. Callers and the Task 5 check expect long text with passages. The system prompt still tells the agent to synthesize text, so the new object adds friction for the model.

**Why it matters**: Existing test logic that reads text content may fail or need rework. The agent may pass an object where text is expected downstream.

**Suggested fix**: Decide the tool contract and keep it stable. If an object is wanted, keep a full `synthesis` text field as the main result and update the prompt and tests to use it. If text is wanted, return the joined text and keep structured fields only in state.

## Minor

### 🟡 Unused policy output model, `src/agents/policy/schema.py:16`

**Problem**: `RetrievePolicyOutput` is defined but never used. The three retriever tools still return plain text. Input models are used, output models are not, so the Pydantic everywhere rule is only half met.

**Why it matters**: Dead models confuse readers. Future edits may use the wrong shape.

**Suggested fix**: Either use the output model in the three retriever tools or remove it until needed.

### 🟡 Unused workflow section model, `src/agents/communication/schema.py:16`

**Problem**: `WorkflowSection` is defined but never referenced. Only `GetFullWorkflowContextInput` and `GetFullWorkflowContextOutput` are used.

**Why it matters**: Extra models add noise and invite drift between duplicates.

**Suggested fix**: Remove `WorkflowSection` or use it as the shared shape for workflow reads.

### 🟡 Route inputs validated then ignored, `src/agents/orchestrator/tools.py:77`

**Problem**: Each route tool builds an input model and assigns it to `_`, then continues with the raw args. Validation can raise, but cleaned values are never used. Readers may think the model shapes the call when it does not.

**Why it matters**: This pattern hides intent and wastes the point of the new schemas.

**Suggested fix**: Use the validated object fields in the calls that follow, or drop the model if no cleanup is needed.

### 🟡 Session init returns two shapes, `src/agents/orchestrator/tools.py:56`

**Problem**: Success returns `model_dump_json` text. Failure returns a plain note string. Callers cannot parse both the same way.

**Why it matters**: Small inconsistency, but session start runs on every request, so all flows touch it.

**Suggested fix**: Return the same JSON shape on both paths, with an error field set on failure.

### 🟡 Changed builder still lacks named exports list, `src/agents/policy/__init__.py:1`

**Problem**: Project rules ask for an explicit `__all__` in every `__init__.py`. The edited policy builder has none. Sibling builders also lack it, so this is an existing gap the change leaves in place.

**Why it matters**: Low risk now, but the rule exists to keep imports clear.

**Suggested fix**: Add `__all__` with the builder name in each edited `__init__.py`, or record that the rule will be met in a later slice.
